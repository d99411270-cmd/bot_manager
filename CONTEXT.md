## Текущее состояние

- Python / aiogram 3, long polling.
- `ConversationService` — оркестратор, не анкета. DeepSeek пишет клиенту; код валидирует и сохраняет факты.
- `/start` нового клиента — точный `START_TEXT`. Дальше любое сообщение, кроме явного валидного телефона/контакта, идёт в AI-менеджера.
- `analyze_intake` остаётся компактным JSON-экстрактором сущностей. Клиентский ответ на вопрос / отказ / оффтоп / «кто вы» / ассортимент идёт через `respond()` + prompt bundle + tool `search_catalog`.
- Вопрос про ассортимент, фрукты, консервацию или цену не подменяется шаблоном `PRODUCT_QUESTION` / `PRODUCT_ASSORTMENT`: `ConversationService` детерминированно вызывает локальный `search_catalog` до AI. Результат передаётся DeepSeek для естественной формулировки; при отбраковке/ошибке используется одноразовый repair-запрос, затем безопасный каталоговый fallback с товарами, производителями, фасовками, ценами и наличием.
- Телефон по-прежнему валидирует код при явном номере или Telegram contact.
- Продукт и объём в CRM по-прежнему не пишутся без телефона. Для каталогового диалога без контакта отдельно сохраняется подтверждённый `current_interest`: если ответ DeepSeek явно отражает категории/подкатегории из найденных позиций, follow-up использует этот интерес вместо поиска по фразе «А какие цены?». При наличии контакта этот интерес также синхронизируется в `product`.
- После квалификации `_handle_ai` применяет `turn.product` / `turn.volume`.
- `product_catalog.py` ищет markdown в `catalog/` (env `STOKOZAVR_CATALOG_DIR`, `catalog/` в корне репо, пакетные данные в wheel). `search("фрукты")` находит `frukty.md`. Пустой поиск — список категорий из заголовков. Поисковый слой нормализует формы категорий (`консервы`/`консерв`/`консервации` → `консервация`) и товарные синонимы (`горошек` → `горошек зелёный`, `кукуруза` → `кукуруза сладкая`, `огурцы` сохраняет точный поиск и добавляет маринованные огурцы).
- `product_catalog.py` принимает коммерческую запись только при наличии всех полей: категория → подкатегория → SKU → производитель → фасовка → цена → статус наличия → дата обновления ISO; неполные строки игнорируются.
- Локальный тестовый каталог: 30 разных основных товарных позиций и 30 конкурентных записей в `catalog/*.md`, по одному конкуренту на каждый основной SKU. Записи конкурентов сохранены для будущего, но текущий поиск, repair/fallback и prompt полностью их игнорируют — запросы «подешевле», «сравнить», «вариант» не показывают и не упоминают конкурентов.
- `product_catalog.py` принимает коммерческую запись только при наличии всех полей: категория → подкатегория → SKU → производитель → фасовка → цена → статус наличия → дата обновления ISO; неполные строки игнорируются.
- В записях каталога поддерживаются отдельные конкурентные варианты через `Тип: конкурент` и `Для SKU`; в текущем продуктовой выдаче они отключены полностью.
- Hatch `force-include`: `prompts` → `stokozavr_bot/prompts`, `catalog` → `stokozavr_bot/catalog`.
- `context_builder.py` — единственная сборка контекста: `profile`, `missing_fields`, `deal_stage`, `returning`, `interests`, `recent_history`. Без `telegram_id`.
- Профиль хранит `original_interests` отдельно от `current_interest`, чтобы переход с творожков на напитки/сок не затирал исходный интерес; профиль также хранит `pending_manager_question` для будущего уведомления менеджеру. `needs_human` сохраняется в совместимом поле комментария CRM. `volume` устойчиво извлекает «36 банок», «20 упаковок», «полпаллеты», «50 литров» и не задаёт вопрос повторно. Явно названный бюджет сохраняется только как сущность, извлечённая DeepSeek; смысловые фразы о зависимости от цены не превращаются кодом в бюджет и не запускают расчёт упаковок. Телефоноподобные российские номера длиной 10/12 цифр не сохраняются: DeepSeek получает `invalid_phone_length` с направлением short/long, а мусор без телефонного сигнала не получает выдуманную длину.
- Раздражение и вопрос о производителе обрабатываются до обычного AI-ответа: короткое извинение без повтора объёма либо явное состояние `needs_human`.
- `sales_state.py` — `deal_stage` отдельно от колонки Google Sheets.
- DeepSeek: модель по умолчанию `deepseek-v4-flash`, `max_tokens=800`, timeout 20 с. В JSON-запросах `thinking: {type: disabled}`. Пустой `content` — явная ошибка `ValueError`.
- `respond` отдаёт OpenAI-compatible `tools` с `search_catalog(query)`. Для сообщений с известным продуктом сервис передаёт локальный каталог в `respond_with_catalog`, поэтому DeepSeek сам понимает сомнение «зависит от цены» по истории/профилю и не повторяет известный объём. Для semantic-запросов цены за единицу intake передаёт `unit_price_request` и `target_product`; `product_catalog.py` считает производную цену только из одной подтверждённой записи и однозначной фасовки (`кг`/`л`/`шт`), передавая AI исходную запись и расчёт. При пустом детерминированном поиске DeepSeek получает явный `CATALOG_RESULT_EMPTY` вместе со списком категорий для смысловой проверки; честный no-match разрешён, цены/наличие и нерелевантные товары блокируются. Цены и статусы в свободном ответе проверяются against `catalog_result` этого вызова; пустой каталог не позволяет заявлять цену/наличие. Одноразовый `repair_response` получает профиль, историю, исходный вопрос, причину и каталог; при подтверждённом каталоге допускается второй recovery-вызов, затем честный ответ/детерминированный unit-price вместо выдумки. Нерешённый вопрос сохраняется в `pending_manager_question` и `needs_human`; уведомление менеджеру пока не отправляется. Intake tools не получает.
- Prompt bundle из `prompts/` подмешивается в `respond`, не в компактный intake.
- JSON-контракты и запрет выдумывать цены/наличие сохранены. `BUSINESS_CONTEXT` в обоих prompt.
- Контактная reply-клавиатура не создаётся; `request_contact` всегда `False`; каждый ответ шлёт `ReplyKeyboardRemove`.
- Имя не добавляется автоматически в каждый ответ; prompt разрешает обращение по имени только в естественных местах.
- `/start` не чистит карточку. Квалифицированный клиент получает returning greeting.
- CRM: `CRMRepository` + Google Sheets + in-memory fake. Объём по-прежнему в `комментарии` как `Объём: ...`.
- SOCKS только для Telegram (`TELEGRAM_PROXY_URL`). Sheets и DeepSeek напрямую.
- Setup-wizard в `tools/setup_wizard.py` без изменений этой фазы.

## Решения и ограничения

- Обязательные столбцы листа `Клиенты` не расширялись. `deal_stage` в таблицу не пишется.
- При неизвестной информации, пустом каталоге, ошибке DeepSeek, опасном утверждении, вопросе про товар/цену без валидного AI-ответа: максимум один repair-запрос с диагностикой причины; если он не дал валидного grounded-ответа — «Я уточню этот вопрос и вернусь к вам.» либо детерминированный ответ из подтверждённого каталога. Цены и наличие не выдумываются. Каталоговые ответы переформулируются естественно и выбирают другой короткий вопрос, если такой же вопрос был соседним ходом; максимум один вопрос.
- Причина исторических 780 ₽, 420 ₽ и «в наличии достаточно»: предыдущие markdown-заглушки содержали эти значения, а `listed_price_amounts()`/проверка наличия считали их разрешёнными. Заглушки очищены; теперь разрешаются только полные структурированные записи с датой. Добавленный каталог локальный и выдуманный для дружеского тестирования; реальные цены и наличие отсутствуют.
- Источник истины карточки — CRM; после рестарта этап по имени/телефону/продукту/объёму.
- Секреты не в репе. Прокси принадлежит только Telegram-session.
- Не делались: Postgres, пуш, деплой.
