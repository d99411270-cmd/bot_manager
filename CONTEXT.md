# CONTEXT.md

## Проект

Отдельный Telegram-бот для «Стокозавра». Путь: `/home/hermes/projects/stokozavr-telegram-bot`. Это не сайт `/home/hermes/projects/zavod`; файлы сайта в этой работе не менялись.

## Текущее состояние

- Создан Python-проект на aiogram 3 с запуском через long polling.
- Реализован строгий первый контакт: имя → телефон → продукт → объём → AI.
- Источник истины — код/FSM. На неквалифицированных этапах отдельный DeepSeek semantic analyzer только классифицирует intent и извлекает сущности; после квалификации используется прежний sales-ответ DeepSeek.
- Intake-контракт: `intent` (`provide_data`, `refusal`, `question`, `greeting`, `offtopic`, `correction`), сущности `name/phone/product/volume`, необязательный `reply`; типы и полный набор полей строго проверяются.
- Код разрешает сохранять данные только в обязательном порядке: имя → телефон → продукт → объём. AI не может перескочить телефон; имя+телефон и продукт+объём принимаются вместе только на допустимом этапе.
- Telegram contact и явно валидный телефон обрабатываются без AI; телефон и объём валидируются кодом.
- Контактная reply-клавиатура полностью удалена: onboarding и отказы не выставляют `request_contact=True`, `KeyboardButton` не создаётся, а Telegram adapter отправляет `ReplyKeyboardRemove` с каждым ответом для удаления старой клавиатуры. Добровольно присланный Telegram contact по-прежнему принимается.
- Отказ от имени/телефона, приветствие, вопрос и off-topic не меняют этап. При отказе бот объясняет пользу и снова задаёт один текущий обязательный вопрос.
- При malformed JSON, timeout или другой ошибке semantic analyzer сомнительный текст не сохраняется; onboarding безопасно остаётся на текущем вопросе.
- `/start` не очищает существующую карточку и возвращает клиента к актуальному вопросу. Если есть имя — оно не теряется. Квалифицированный клиент с именем и продуктом получает returning greeting (имя + прошлый интерес, один вопрос), а не текст нового `/start`.
- Утверждённые тексты первого контакта (`START_TEXT`) зафиксированы точными regression-тестами.
- DeepSeek подключён через OpenAI-compatible HTTP API, имеет timeout 20 секунд, `max_tokens=350` и строгую проверку типов JSON.
- Профиль и последние сообщения передаются в каждый AI-запрос. Перед `respond` дополнительно уходит структурированный контекст: `known_fields`, `stage`, `interests`, `returning`.
- Семь файлов из `prompts/` склеиваются loader'ом `prompt_bundle.py` в фиксированном порядке и подмешиваются в system prompt для `analyze_intake` и `respond`. Поиск: env `STOKOZAVR_PROMPTS_DIR`, `Path(__file__).resolve().parents[2]/prompts`, затем `importlib.resources` (`stokozavr_bot/prompts`). В wheel файлы кладутся через hatch `force-include`: `prompts` → `stokozavr_bot/prompts`.
- JSON-контракты и запрет выдумывать цены/наличие сохранены; `BUSINESS_CONTEXT` остаётся в обоих prompt вместе с bundle.
- На product-stage вопросы «а какая у вас есть?»/«что продаёте?» получают: «В Стокозавре представлены основные категории продуктов для оптовых закупок: бакалея, напитки, консервация и другие товары. » + «Подскажите, какая категория вам интересна?». Дословный `PRODUCT_QUESTION` на такой вопрос не повторяется. Пустой, повторяющий или выдумывающий ассортимент AI reply заменяется этим префиксом.
- Отказ от телефона: «Номер нужен, чтобы закрепить за вами информацию и при необходимости быстро связаться по вопросам заказа. » Пустая формула «номер нужен для связи» не используется.
- Реализованы детерминированный сбор продукта/объёма, статусы и полная история сообщений.
- Реализован CRM-интерфейс, Google Sheets repository и in-memory fake.
- Ответ ограничен одним вопросом; опасный или многовопросный AI-ответ заменяется безопасным.
- Цена/наличие до объёма не выдумываются: бот подтверждает уточнение и повторяет текущий обязательный вопрос.
- Искусственная задержка убрана с onboarding/FSM. Она применяется вероятностно только к валидным AI-ответам после квалификации, по диапазонам 1–2/2–4/3–6 секунд; typing работает во время AI-запроса.
- Prompt injection передаётся модели только как пользовательские данные; извлечённые значения всё равно проходят кодовые stage-gates и не могут менять порядок FSM.
- Подготовлены `.env.example`, Dockerfile и `docker-compose.yml` без секретов.
- Для Telegram Bot API добавлен опциональный явный SOCKS5 через
  `TELEGRAM_PROXY_URL` и официальный `AiohttpSession(proxy=...)` aiogram 3. По
  умолчанию значение пустое; Google Sheets и DeepSeek остаются на прямом соединении.
- Добавлена совместимая зависимость `aiohttp-socks>=0.10.1,<0.13`; в lock-файле
  зафиксирована версия `0.12.0`.
- Добавлен отдельный одноразовый stdlib setup-wizard в `tools/setup_wizard.py`: он слушает только `127.0.0.1:18080`, принимает данные только по секретному пути, валидирует и атомарно сохраняет один JSON-файл с правами `0600`, не затрагивая код бота.
- `GoogleSheetsCRMRepository.get_client()` безопасно нормализует пустую ячейку `комментарии` (`None` от `get_all_records`) в пустую строку; для такой строки `volume` остаётся `None`.

## Решения и ограничения

- Обязательные столбцы листа `Клиенты` оставлены без расширения. Объём записывается в `комментарии` как `Объём: ...`.
- При неизвестной информации, ошибке DeepSeek, опасном утверждении или более чем одном вопросе ответ строго: «Я уточню этот вопрос и вернусь к вам.»
- FSM aiogram помогает маршрутизации, но источник истины — CRM; после перезапуска этап восстанавливается по имени, телефону, продукту и объёму.
- Секреты не добавлены. Любые JSON-файлы и `.env` игнорируются Git.
- Системная маршрутизация и proxy-переменные не меняются: прокси принадлежит только
  Telegram-session.
- Реальные Telegram, Google Sheets и DeepSeek подключения проверены на Beget; секреты хранятся только в закрытых серверных файлах.
