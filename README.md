# Telegram-бот «Стокозавр»

Рабочий каркас Telegram-менеджера «Иван»: код строго управляет порядком имя → телефон → продукт → объём, а отдельный DeepSeek-анализатор понимает смысл сообщений на этапах intake. Профиль и переписка сохраняются в Google Sheets.

## Что умеет

- строгий путь первого контакта: **имя → телефон → продукт → объём → AI-диалог**;
- телефон можно написать или добровольно отправить как Telegram contact; оба варианта обрабатываются детерминированно;
- бот не показывает кнопку `request_contact`, не создаёт `KeyboardButton` и каждым ответом отправляет `ReplyKeyboardRemove`, чтобы скрыть ранее показанную клавиатуру;
- semantic intake возвращает строгий контракт `intent` (`provide_data`, `refusal`, `question`, `greeting`, `offtopic`, `correction`), `entities` (`name`, `phone`, `product`, `volume`) и необязательный `reply`;
- только код решает, какие сущности сохранить и какой обязательный вопрос задать следующим: AI не может перескочить телефон или изменить FSM;
- можно сообщить имя с телефоном одним сообщением, а после контакта — продукт с объёмом; телефон и объём дополнительно валидируются кодом;
- отказ от имени или телефона ничего не сохраняет и не меняет статус: бот кратко объясняет пользу и повторяет текущий вопрос;
- `/start` продолжает текущий этап и не очищает существующую карточку;
- при malformed JSON, timeout или другой ошибке intake-анализатора сомнительный текст не принимается как данные, а текущий этап безопасно продолжается;
- AI получает профиль и последние 10 записей истории;
- системные prompt DeepSeek собираются из папки `prompts/` (личность, психология продаж, правила диалога, возражения, память компании, память клиента, сценарии) плюс JSON-контракт и запрет выдумывать цены/наличие;
- перед `respond` в модель уходит структурированный контекст: известные поля, этап, интересы и флаг возвращающегося клиента;
- `/start` для клиента с именем и прошлым продуктом напоминает интерес и не начинает диалог как с нового;
- после квалификации DeepSeek отвечает отдельным строго проверяемым JSON (`reply`, `product`, `volume`, `needs_human`), но также не управляет FSM;
- статусы: `новый`, `ожидает телефон`, `уточнение продукта`, `уточнение объёма`, `квалифицирован`;
- до получения объёма вопросы о цене и наличии подтверждаются без выдумки, затем бот повторяет ровно текущий обязательный вопрос;
- безопасный ответ при неизвестной информации или нарушении формата: **«Я уточню этот вопрос и вернусь к вам.»**;
- дополнительный фильтр блокирует любые неподтверждённые цены и утверждения о наличии;
- каждый ответ содержит не более одного вопроса; некорректный AI-ответ заменяется безопасным;
- на вопрос об ассортименте на этапе продукта бот отвечает: «В Стокозавре представлены основные категории продуктов для оптовых закупок: бакалея, напитки, консервация и другие товары.» и спрашивает, какая категория интересна; дословный вопрос «какая продукция вас интересует?» на такой вопрос не повторяется; пустой, повторяющий или выдумывающий ассортимент AI-ответ заменяется этим детерминированным текстом;
- отказ назвать телефон объясняется пользой: номер нужен, чтобы закрепить информацию и при необходимости быстро связаться по заказу; пустая формула «номер нужен для связи» не используется;
- имя, телефон, валидация и обязательные FSM-вопросы отправляются сразу;
- задержка применяется вероятностно только к содержательным AI-ответам после квалификации: 1–2 с для коротких, 2–4 с для средних и 3–6 с для длинных;
- CRM скрыта за интерфейсом `CRMRepository`, поэтому Google Sheets можно заменить;
- `InMemoryCRMRepository` и fake-компоненты позволяют тестировать без внешних ключей.

Бот представляется Иваном и никогда не сообщает пользователю, что использует AI.

## Быстрый запуск

Нужен Python 3.10+ и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env
uv sync --extra dev
uv run python -m stokozavr_bot
```

Перед запуском заполните `.env`. Реальные токены и JSON сервисного аккаунта **не кладите в репозиторий**.

## Настройка Telegram

1. Создайте бота у `@BotFather`.
2. Запишите токен в `TELEGRAM_BOT_TOKEN` локального `.env`.
3. Если Telegram Bot API должен идти через SOCKS5, задайте, например,
   `TELEGRAM_PROXY_URL=socks5://127.0.0.1:10808`. По умолчанию переменная пустая и
   соединение с Telegram выполняется напрямую.

Прокси передаётся явно только в официальный `AiohttpSession(proxy=...)` клиента
aiogram. Google Sheets и DeepSeek эту настройку не используют и продолжают работать
напрямую. Не задавайте системные `HTTP_PROXY`, `HTTPS_PROXY` или `ALL_PROXY`, если
нужно проксировать только Telegram.

## Настройка DeepSeek

Создайте API-ключ DeepSeek и укажите `DEEPSEEK_API_KEY`. Клиент использует OpenAI-compatible endpoint `/chat/completions`. URL и модель можно заменить через `DEEPSEEK_BASE_URL` и `DEEPSEEK_MODEL`. Таймаут и предел ответа задаются `DEEPSEEK_TIMEOUT_SECONDS` (по умолчанию 20) и `DEEPSEEK_MAX_TOKENS` (350). Вероятность естественной задержки задаётся `REPLY_DELAY_PROBABILITY` от 0 до 1.

## Настройка Google Sheets

1. В Google Cloud создайте сервисный аккаунт и JSON-ключ.
2. Создайте таблицу и поделитесь ей с email сервисного аккаунта с правом редактирования.
3. Укажите ID таблицы в `GOOGLE_SPREADSHEET_ID`.
4. Положите JSON **вне репозитория** и укажите абсолютный путь в `GOOGLE_SERVICE_ACCOUNT_FILE`.

При первом старте репозиторий создаст отсутствующие листы. Если лист уже есть, первая строка должна строго совпадать:

**Клиенты**

`telegram_id, username, имя клиента, телефон, интересующая продукция, статус клиента, дата первого обращения, дата последнего обращения, комментарии`

**История сообщений**

`дата, telegram_id, сообщение клиента, ответ Ивана`

В заданной схеме нет отдельной колонки объёма, поэтому он сохраняется в `комментарии` с префиксом `Объём:`. Это сохраняет обязательную структуру листа без потери данных.

## Docker Compose

```bash
cp .env.example .env
mkdir -p secrets
# вручную поместите ключ в secrets/google-service-account.json
docker compose up --build
```

Папка `secrets` и любые `*.json` игнорируются Git. Docker/Compose здесь только подготовлены; проект не развёртывался.

## Проверка

```bash
uv run --extra dev ruff check .
uv run --extra dev ruff format --check .
uv run --extra dev pytest -q
```

Тесты не обращаются к Telegram, DeepSeek или Google: HTTP и CRM заменены fake/in-memory реализациями.

## Архитектура

- `service.py` — детерминированный сценарий/FSM разговора и правила безопасности;
- `prompt_bundle.py` — загрузка семи файлов из `prompts/` (env `STOKOZAVR_PROMPTS_DIR`, корень репозитория, затем пакет в wheel);
- `telegram.py` — aiogram 3, FSM и принудительное удаление старой reply-клавиатуры;
- `deepseek.py` — OpenAI-compatible HTTP-клиент, prompt bundle и строгая проверка structured response;
- `google_sheets.py` — реализация CRM на Google Sheets;
- `repositories.py` — протокол CRM и in-memory реализация;
- `models.py` — доменные модели;
- `__main__.py` — сборка зависимостей, изолированное подключение SOCKS5-session только к Telegram Bot API и polling.

## Ограничения

- Источник подтверждённых цен и складских остатков не подключён, поэтому бот никогда не выдумывает эти данные и передаёт вопрос менеджеру.
- Для production желательно подключить персистентное FSM-хранилище (например Redis), но бизнес-состояние первого контакта уже восстанавливается из CRM после рестарта.
- Логи не должны содержать токены или содержимое ключа сервисного аккаунта.
