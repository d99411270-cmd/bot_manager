# Telegram-бот «Стокозавр»

Telegram-менеджер «Иван»: DeepSeek пишет клиенту, код только валидирует и сохраняет факты. Профиль и переписка — в Google Sheets.

## Что умеет

- `/start` нового клиента отдаёт точный `START_TEXT`; дальше любое сообщение, кроме явного валидного телефона/контакта, идёт в AI-менеджера;
- код сохраняет только проверенные `name` / `phone` / `product` / `volume`; телефон валидируется кодом, продукт и объём не пишутся без телефона (нельзя перескочить контакт);
- клиентский ответ на вопрос, отказ, приветствие или оффтоп пишет `respond()` с prompt bundle и при необходимости `search_catalog`; шаблоны анкеты — только если это не вопрос про товар/цену и AI не дал валидный текст;
- вопрос «а какая у вас есть?» / «какие фрукты есть?» / «кто вы» не требует телефон и не повторяет анкету, если AI дал короткий безопасный ответ (≤1 вопрос, без цен и наличия);
- имя и телефон из вопроса сохраняются тихо и не перебивают ответ про товар;
- DeepSeek `respond` сам вызывает инструмент `search_catalog`, если вопрос про ассортимент; без tool конкретные позиции не называет;
- файловый каталог `catalog/*.md` (env `STOKOZAVR_CATALOG_DIR`, корень репозитория, пакет в wheel); валидатор принимает только полную строку `категория → подкатегория → SKU → производитель → фасовка → цена → статус наличия → дата обновления`;
- при ошибке AI, пустом ответе, выдуманной цене или вопросе про товар без валидного reply клиенту уходит только **«Я уточню этот вопрос и вернусь к вам.»**, не шаблон анкеты;
- отказ назвать телефон может уйти клиенту текстом Ивана, если ответ валиден; иначе — запасная формулировка про закрепление заявки;
- после квалификации `_handle_ai` обязательно применяет `turn.product` / `turn.volume` в профиль;
- Telegram contact и явно валидный телефон обрабатываются без AI; кнопка `request_contact` не показывается, `KeyboardButton` не создаётся, каждый ответ шлёт `ReplyKeyboardRemove`;
- semantic intake остаётся компактным JSON-экстрактором: `intent` (`provide_data`, `refusal`, `question`, `greeting`, `offtopic`, `correction`), `entities`, необязательный `reply`;
- `/start` продолжает текущий этап и не очищает существующую карточку;
- при malformed JSON, пустом `content`, timeout или другой ошибке сомнительный текст не сохраняется;
- AI получает компактный контекст из `context_builder` (профиль, `missing_fields`, `deal_stage`, `returning`, интересы, недавняя история) — не сырой dump таблицы;
- `deal_stage` (`new_lead`, `discovery`, `product_selection`, `qualified`, `quote_requested`, `objection`, `ready_to_order`) считается отдельно от статус-строк Google Sheets;
- системный prompt `respond` собирается из `prompts/` (личность, психология, правила, возражения, память компании, память клиента, сценарии) плюс JSON-контракт;
- модель по умолчанию `deepseek-v4-flash`, `max_tokens=800`; в JSON-запросах `thinking` выключен;
- статусы листа: `новый`, `ожидает телефон`, `уточнение продукта`, `уточнение объёма`, `квалифицирован`;
- цена и наличие не выдумываются; неполная/недатированная запись каталога не является подтверждением, а опасный или многовопросный AI-ответ заменяется безопасным: **«Я уточню этот вопрос и вернусь к вам.»**;
- раздражение («нудный», «душный» и варианты) распознаётся отдельно: Иван признаёт проблему, сокращает ответ и не повторяет вопрос про объём;
- запрос производителя без подтверждения переводится в CRM-состояние `needs_human`, не обещая абстрактно «вернуться»;
- имя, телефон и fallback-вопросы анкеты уходят сразу; задержка вероятностно только у валидных AI-ответов после квалификации;
- CRM скрыта за `CRMRepository`; `InMemoryCRMRepository` позволяет тестировать без ключей.

Бот представляется Иваном и никогда не сообщает пользователю, что использует AI.

## Быстрый запуск

Нужен Python 3.10+ и [uv](https://docs.astral.sh/uv/).

```bash
cp .env.example .env
uv sync --extra dev
uv run python -m stokozavr_bot
```

Перед запуском заполните `.env`. Реальные токены и JSON сервисного аккаунта **не кладите в репозиторий**.

## Настройка Telegram

1. Создайте бота у `@BotFather`.
2. Запишите токен в `TELEGRAM_BOT_TOKEN` локального `.env`.
3. Если Telegram Bot API должен идти через SOCKS5, задайте, например,
   `TELEGRAM_PROXY_URL=socks5://127.0.0.1:10808`. По умолчанию переменная пустая и
   соединение с Telegram выполняется напрямую.

Прокси передаётся явно только в официальный `AiohttpSession(proxy=...)` клиента
aiogram. Google Sheets и DeepSeek эту настройку не используют и продолжают работать
напрямую. Не задавайте системные `HTTP_PROXY`, `HTTPS_PROXY` или `ALL_PROXY`, если
нужно проксировать только Telegram.

## Настройка DeepSeek

Создайте API-ключ DeepSeek и укажите `DEEPSEEK_API_KEY`. Клиент использует OpenAI-compatible endpoint `/chat/completions`. URL и модель можно заменить через `DEEPSEEK_BASE_URL` и `DEEPSEEK_MODEL` (по умолчанию `deepseek-v4-flash`). Таймаут и предел ответа задаются `DEEPSEEK_TIMEOUT_SECONDS` (20) и `DEEPSEEK_MAX_TOKENS` (800). Вероятность естественной задержки задаётся `REPLY_DELAY_PROBABILITY` от 0 до 1.

## Настройка Google Sheets

1. В Google Cloud создайте сервисный аккаунт и JSON-ключ.
2. Создайте таблицу и поделитесь ей с email сервисного аккаунта с правом редактирования.
3. Укажите ID таблицы в `GOOGLE_SPREADSHEET_ID`.
4. Положите JSON **вне репозитория** и укажите абсолютный путь в `GOOGLE_SERVICE_ACCOUNT_FILE`.

При первом старте репозиторий создаст отсутствующие листы. Если лист уже есть, первая строка должна строго совпадать:

**Клиенты**

`telegram_id, username, имя клиента, телефон, интересующая продукция, статус клиента, дата первого обращения, дата последнего обращения, комментарии`

**История сообщений**

`дата, telegram_id, сообщение клиента, ответ Ивана`

В заданной схеме нет отдельной колонки объёма, поэтому он сохраняется в `комментарии` с префиксом `Объём:`. Это сохраняет обязательную структуру листа без потери данных.

## Docker Compose

```bash
cp .env.example .env
mkdir -p secrets
# вручную поместите ключ в secrets/google-service-account.json
docker compose up --build
```

Папка `secrets` и любые `*.json` игнорируются Git. Docker/Compose здесь только подготовлены; проект не развёртывался.

## Архитектура

- `service.py` — оркестратор: валидация фактов, тихий захват имени/телефона, fallback;
- `product_catalog.py` — поиск и строгий парсинг markdown-каталога; коммерческие поля выдаются только из полной датированной записи;
- `context_builder.py` — единственная сборка контекста модели;
- `sales_state.py` — `deal_stage` по полям и intent, отдельно от колонки статуса;
- `prompt_bundle.py` — загрузка семи файлов из `prompts/` (env `STOKOZAVR_PROMPTS_DIR`, корень репозитория, затем пакет в wheel);
- `telegram.py` — aiogram 3, FSM и принудительное удаление старой reply-клавиатуры;
- `deepseek.py` — OpenAI-compatible HTTP-клиент, prompt bundle и tool `search_catalog` в `respond`, строгая проверка JSON, `thinking` disabled;
- `google_sheets.py` — реализация CRM на Google Sheets;
- `repositories.py` — протокол CRM и in-memory реализация;
- `models.py` — доменные модели;
- `__main__.py` — сборка зависимостей, изолированное подключение SOCKS5-session только к Telegram Bot API и polling.

## Ограничения

- Источник подтверждённых цен и складских остатков не подключён, поэтому бот никогда не выдумывает эти данные и передаёт вопрос менеджеру.
- Для production желательно подключить персистентное FSM-хранилище (например Redis), но бизнес-состояние первого контакта уже восстанавливается из CRM после рестарта.
- Логи не должны содержать токены или содержимое ключа сервисного аккаунта.
